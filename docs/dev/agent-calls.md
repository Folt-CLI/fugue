# Agent calls

This inventory records every provider adapter `.run(...)` call site under
`src/fugue`. Locations refer to the current source. Each call site appears once;
implementation and repair share one call site. Forwarding wrappers appear too,
so multiple rows can describe the path of a single request to a provider.
Calls to subprocesses, event loops, the engine and conversation loops are excluded.

The class column describes the work requested, not the agent's reliability or
whether its output is repeatable:

- **Judgment**: interpreting intent, investigating code, choosing wording or
  producing changes requires judgment. Deterministic preparation and validation
  around the request do not make that work deterministic.
- **Deterministic forwarding**: code routes an existing request without asking
  for another judgment. The forwarded request retains its original work.

The deterministic parts column distinguishes code behavior from instructions.
An instruction to an agent is not, by itself, a validation performed by Fugue.
These are inventory classes, not new glossary terms, roles or capabilities.

## Checking completeness

Search all of `src/fugue` for `.run(` and inspect each receiver. Match calls on
provider adapters, including wrappers, to the eleven locations above. Exclude
`asyncio.run`, `subprocess.run`, engine calls and conversation-loop calls. Check
the prompt builders as well as the call expressions: `interview/flow.py`, for
example, constructs requests but does not itself call a provider adapter.

Check implementation and repair against the single shared call site, and count
forwarding wrappers separately without treating them as additional tasks for an
agent. Recheck locations and instructions when the source changes; this document
describes current behavior and does not propose moving judgment into code.
